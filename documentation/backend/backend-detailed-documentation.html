DELETE /api/users/:id

routes/users.js:203-286 Frontend: UserManagement.handleDeleteUser()
Purpose

Performs user account deactivation (soft delete) with comprehensive business rule validation and role-based access control.

Middleware Stack
authenticateToken requireAdminRole validateUserParam
Model Methods Called
User.findById()
User.findWithFilters()
User.delete() (soft)
Complex Business Rules

Users cannot delete their own accounts to prevent accidental lockouts.

Regular admin users cannot delete other admin users. Only god_mode users have this privilege.

Cannot delete the last admin for a store. Each store must maintain at least one admin user.
Business Logic Flow
// 1. Self-deletion check
if (targetUser.id === currentUser.id) {
  return 403; // Cannot delete own account
}

// 2. Admin deletion privilege check
if (targetUser.role === 'admin') {
  if (currentUser.role !== 'god_mode') {
    return 403; // Regular admins can't delete admins
  }
  
  // 3. Last admin check for god_mode users
  const activeAdmins = await User.findWithFilters({
    role: 'admin',
    store_id: targetUser.store_id,
    is_active: true
  });
  
  if (activeAdmins.length === 1) {
    return 400; // Cannot delete last admin
  }
}

// 4. Perform soft delete
await User.delete(targetUser.id);
Success Response (200)
{

  "user": {
    "id": 5,
    "name": "John Doe",
    "is_active": false,
    "deactivated_at": "2025-08-16T14:30:00Z"
  }
}

Middleware Functions

File: middleware/auth.js

Authentication Middleware

authenticateToken
JWT Token Validation
  • Extracts Bearer token from Authorization header
  • Verifies JWT signature and expiration
  • Adds user information to request object
  • Returns 401 for invalid/expired tokens
requireAdminRole
Role-Based Access Control
  • Checks user role from authenticated request
  • Allows 'admin' and 'god_mode' roles
  • Returns 403 for insufficient permissions
  • Used for administrative endpoints
requireStoreAdmin
Store-Level Access Control
  • Validates user has admin rights for specific store
  • god_mode users can access all stores
  • Regular admins limited to assigned store
  • Used for inventory and store management

    [id]

  // Business logic validation
  if (!isValidOperation(data)) {

Soft Delete Pattern

// Preserve data integrity
static async delete(id) {
  const [result] = await db.execute(
    `UPDATE users 
     SET is_active = FALSE, 
         updated_at = CURRENT_TIMESTAMP 
     WHERE id = ?`,
    [id]
  );
  return result.affectedRows > 0;
}

// Filter out inactive by default
static async findActive() {
  const [rows] = await db.execute(
    'SELECT * FROM users WHERE is_active = TRUE'

  return rows;
}
