calculateRunningBalance(transactions)

Line 93-113
calculateRunningBalance(transactions: Array): Array
Purpose

Calculates running balance for transaction register display, ensuring chronological order and handling concurrent transactions properly.

Algorithm
  1. Sort transactions by date + ID (chronological)
  2. Initialize running balance to 0
  3. Add quantity_change to running balance
  4. Attach calculated_running_balance to each transaction
Business Logic
  • Uses transaction ID as tiebreaker for same timestamp
  • Ensures audit trail accuracy
  • Handles negative adjustments (fills, expirations)
  • Handles positive adjustments (returns, receipts)
Sample Input/Output
// Input transactions
[
  { id: 1, quantity_change: 100, transaction_date: "2024-01-01" },
  { id: 2, quantity_change: -30, transaction_date: "2024-01-02" },

handleDeleteUser()

Line 315-345
async handleDeleteUser(): Promise<void>
Purpose

Performs user account deactivation (soft delete) with comprehensive business rule validation and god_mode privilege handling.

API Calls
userAPI.delete() Backend: DELETE /api/users/:id
Business Rules Enforced
  • Self-Protection: Cannot delete own account
  • Admin Protection: Regular admins cannot delete other admins
  • God Mode Override: god_mode users can delete admins
  • Last Admin Rule: Cannot delete last admin for a store
Validation Logic Flow
// Client-side validation
if (selectedUser.id === user.id) {
  setError("Cannot delete your own account");
  return;
}

// Server validates:
// 1. Admin deletion privileges (god_mode required)
// 2. Last admin per store rule
// 3. User exists and is active
Possible Server Responses

{
  "message": "User deactivated successfully"
}

{
  "error": "Admin users cannot be deleted. To remove admin access, change their role to user instead."
}

{
  "error": "Cannot delete the last admin for this store. Each store must have at least one admin."
}

Error Handling Patterns

Frontend Error Handling Strategy

1. API Error Extraction
try {
  await apiCall();
} catch (err) {
  const errorMessage = 
    err.response?.data?.message || 
    err.response?.data?.error ||
    err.message ||
    'An error occurred';
  setError(errorMessage);
}
2. Validation Error Arrays
// Server returns validation errors
{
  "errors": [
    {"field": "email", "message": "Invalid format"},
    {"field": "password", "message": "Too short"}
  ]
}

// Frontend handling
const errorMessages = error.response?.data?.errors
  ?.map(err => `${err.field}: ${err.message}`)
  .join(', ') || 'Validation failed';

const handleChange = (e) => {
  const { name, value, type, checked } = e.target;
  setFormData(prev => ({
    ...prev,
    [name]: type === 'checkbox' ? checked : value
  }));
};

// Update URL when filters change
const updateFilters = (key, value) => {
  const newParams = new URLSearchParams(searchParams);
  if (value) {
    newParams.set(key, value);
  } else {
    newParams.delete(key);
  }
  setSearchParams(newParams);
};
